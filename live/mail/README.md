# משלוח כתבות מהשרת

`election-news/video_mail.py` רץ ב-GitHub Actions אחת לשעה, מוריד וידאו מקורי ציבורי, מנרמל ל-MP4 עם תמונה וקול ומחלק לחלקים של עד 8 MiB לצירוף במייל. אין תלות בצ'אט או בדפדפן בזמן הריצה.

המשלוח משתמש בחיבור Gmail הקיים של `yemot-mail`. הסודות נשארים ב-Cloudflare. גישת השרת מאומתת ב-GitHub OIDC: מאגר `SHMUEL-LAMED/07`, מזהה `1390638770`, ענף `main` ורק workflow `election-news.yml`. הנמען קבוע לחשבון הבעלים; אין בנתיבים החדשים גישה כללית לקריאת מיילים או שליחה לנמענים אחרים.

הקוד החי של שירות הדואר נלקח מגרסה `85be28d1`. הוא אינו מועלה למאגר הזה: כדי לבנות את הקובץ המאוחד, שומרים עותק נוכחי ב-`live/mail/base.mjs` ומריצים `python scripts/build-mail-video.py`. הבנייה מוסיפה נתיבים בלבד ומשאירה את ההתנהגות הקיימת. לפני פריסה יש לוודא שהגרסה החיה לא השתנתה ולהשוות את הבסיס לעורך; חזרה לגרסה הקודמת זמינה ב-Cloudflare Deployments.

אחרי פריסת הגשר, מפעילים ידנית את workflow עם `video_email=true` ו-`video_mail_check_only=true` לבדיקת חיבור בלי משלוח. להפעלה רגילה מבטלים check-only. התזמון השעתי הוא בדקה 37; זמני GitHub Actions יכולים להתעכב. אם אין וידאו חדש לא נשלח מייל. פריטים חסומים נשארים מחוץ לקובץ ונרשמים ביומן.

קבלות משלוח ומזהה Message-ID קבוע לכל חלק מונעים שליחה חוזרת לאחר ניסיון נוסף. במקרה של תשובת רשת לא חד משמעית נעצרים ומחפשים את המשלוח הקיים בדואר שנשלח, במקום לשלוח שוב באופן עיוור. קובץ גדול נשלח בכמה חלקי MP4; אין כאן העלאה לדרייב או הרחבה של הרשאות Google.
